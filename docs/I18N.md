# Website languages and shared visual system

The site supports `pt-BR` (default), `en` and `es`. UI routes live under `apps/web/app/[locale]`; API routes and engineering downloads keep their original URLs. The proxy redirects unprefixed UI links using the functional `rs-locale` preference cookie, validates the locale and forwards a server-only request locale. It does not rewrite a translated route back through the proxy. Document language, metadata and alternate language links are rendered for the selected route.

`apps/web/i18n/config.ts` owns URL rules. `catalog.ts` reads the source-key catalogs; `T` renders translated text without HTML wrappers or post-render DOM translation. `LocalLink` preserves the active language while leaving APIs, download filenames, fragments and external destinations untouched. Machine identifiers, JSON fields, code and manufacturer documents retain their source language. User-provided competition/team names are never translated. Numbers and room-expiry dates use the selected locale for presentation only.

The circular flag is a native keyboard-accessible language select with an invisible visual label and an accessible localized name. The full language names remain in its option list. On the laboratory and competition screens, language changes update the context and URL without remounting the match/session, preserving in-memory room credentials. Content pages navigate normally to retrieve their server-rendered localized articles. No credential is placed in browser persistence or a URL to support language switching.

Portuguese and Spanish learning/reference articles are in `docs/i18n`; the original detailed English source and historical verification log remain in the repository. The verification pages explain how to find that original record. Case guides exist in all three languages, and the ZIP contains all of them alongside the four STL files and editable sources. Policy/contribution copy is maintained in `i18n/policies.ts`.

The public presentation, documentation, hardware and competition screens use the laboratory's dark palette and mint accents. Brand artwork and flags are original SVG code. CSS handles entrance, hover and decorative field motion; the intersection observer reveals lower sections. All motion is disabled for `prefers-reduced-motion: reduce`; content remains available without the observer.

## Validation

Run `npm run typecheck`, `npm test`, `npm run build`, then the local server and `npm run test:site-smoke` / `npm run test:i18n-smoke`. The latter checks 69 localized pages, document language, navigation, guide selection, saved locale redirects, unknown articles and an unchanged protected API endpoint. Unit tests cover URL exclusions, prefix switching, source fallbacks, machine identifiers, decimal formatting and catalog parity. Browser checks exercise native selection and a connected private-room language change.

Development uses `next dev --webpack` while Turborepo continues orchestrating the monorepo. In this environment the default Turbopack development server repeatedly refreshed the localized page without source edits; the explicit webpack development mode restored stable hydration and working controls. Production builds continue to use Next.js's default build pipeline. The production database guard still requires dedicated Neon; local PostgreSQL room tests run in development mode.
